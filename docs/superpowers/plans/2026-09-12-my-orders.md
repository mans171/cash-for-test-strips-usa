# My Orders — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A seller who is signed in can see the orders (quote requests and bulk enquiries) they submitted on cash4teststripsusa.com; signing in stays optional and never blocks a submission.

**Architecture:** Add a nullable `user_id` to `leads` with an RLS policy letting an authenticated user read only their own rows. Both public lead routes attach the signed-in user's id when a session cookie is present (and nothing otherwise). A new `/orders` server page lists the user's leads with the matched buyer's name and a bonus note; the nav shows "My orders" when signed in; the two success screens nudge toward an account.

**Tech Stack:** Next.js 15 App Router, Supabase (`@supabase/ssr` server client already at `lib/supabase/server.ts`; anon client at `lib/supabase.ts`), Tailwind, vitest.

**Spec:** Feldon 2026-09-12: "They should still be able to make an account … That way they can see the orders they submitted." Donna's proposal he approved: (1) save the signed-in user's id on each order when logged in, optional login never required; (2) a "My orders" page with matched buyer and date; (3) a "Sign in to track your orders" nudge after submitting.

**Interfaces:**

- [ ] **Step 1: Migration**
```sql
-- Sellers who are signed in can see the orders they submitted. Signing in stays
-- optional: user_id is null for anonymous submissions and nothing reads it then.
alter table public.leads
  add column if not exists user_id uuid references auth.users (id) on delete set null;
create index if not exists leads_user_id_idx on public.leads (user_id);

-- anon/authenticated inserts keep working via the existing leads_insert_anon policy.
-- Reading is new and scoped to the row's owner.
create policy "leads_select_own"
  on public.leads for select
  to authenticated
  using (user_id = auth.uid());
```
Check `supabase/migrations/20260614000000_initial_schema.sql` for the exact shape of `leads_insert_anon` (its `to` role list) — if it is `to anon` only, add `to anon, authenticated` semantics by creating a second policy `leads_insert_authenticated` with the same `with check` so a signed-in seller's insert is not refused.
